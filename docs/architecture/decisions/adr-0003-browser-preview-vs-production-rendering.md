# ADR-0003: Separate Browser Preview from Production Rendering

**Status:** Accepted  
**Revision date:** 2026-08-05

## Context

Browser Web Audio is appropriate for responsive editing and audition, but browser timing, implementations, and device conditions are not sufficient evidence for deterministic production exports.

## Decision

Treat `BrowserAudioEngine` as a preview runtime. Production exports are generated by dedicated workers from a versioned render manifest containing the exact project revision, checksum, engine version, seed, tick range, scope, and output settings.

WAV/PCM is the first certification format. Lossy formats and stems are derived after deterministic WAV output is validated.

## Consequences

- Editor playback can remain low-latency and browser-specific.
- Production output has immutable inputs and auditable artifacts.
- Preview and worker implementations must share canonical device and routing semantics.
- A durable render-job state machine and asset-verification boundary are required.

## Rejected Alternatives

- Recording the browser destination as the production export
- Rendering from mutable current project state without a revision checksum
- Implementing MP3/OGG first without deterministic PCM evidence
