# Architecture Decision Records

Architecture decision records capture choices that constrain future implementation. Accepted ADRs are durable; superseded ADRs remain in the repository with an updated status.

| ADR | Decision | Status |
|---|---|---|
| [ADR-0001](adr-0001-canonical-project-and-revisions.md) | Canonical project model and immutable revisions | Accepted |
| [ADR-0002](adr-0002-local-first-platform-sync.md) | Local-first persistence with explicit platform synchronization | Accepted |
| [ADR-0003](adr-0003-browser-preview-vs-production-rendering.md) | Separate browser preview from production rendering | Accepted |
| [ADR-0004](adr-0004-device-parameters-and-production-audio-graph.md) | Canonical device parameters and explicit production audio graph | Accepted |

## ADR Template

Each ADR should state:

- Status
- Context
- Decision
- Consequences
- Rejected alternatives
- Revision date
